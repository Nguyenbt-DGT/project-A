# AI Implementation Knowledge Base

Owned by: **Dev Back End Agent** (implementation), referenced by all agents.

## Provider
- Default: **OpenAI API** (`gpt-4o-mini`), called via the `openai` Node SDK.
- Abstracted behind `src/services/aiService.ts::generateLessonPlan(...)` so the provider is swappable via an `AI_PROVIDER` env var without touching callers.
- API key via `OPENAI_API_KEY` env var — never hardcoded, never logged.

## Structured Output Contract
The AI must return **strict JSON** (use OpenAI JSON mode / `response_format={"type": "json_object"}`) matching:
```json
{
  "title": "string",
  "warm_up": "string",
  "concept_explanation": "string",
  "activities": [
    { "name": "string", "rule": "string", "duration_min": 10 }
  ],
  "closing": "string"
}
```
`renderService.ts` then merges this JSON with the teacher-provided `video_links` and `image_url` (which are NOT invented by the AI — they come verbatim from user input) into the final standalone HTML document.

## System Prompt Guidelines
- State the audience explicitly: "Learners aged {age_from}-{age_to} years old, English language class."
- Require simple vocabulary, short sentences, encouraging tone appropriate for early-childhood education.
- Require exactly `num_activities` entries in `activities`, each a simple game with a clear, safe, classroom-friendly rule, feasible within `activity_duration_min` minutes.
- If `total_lesson_time_min` is provided, instruct the model to keep warm-up + activities + closing roughly within that budget and mention pacing in `closing`.
- Explicitly forbid unsafe, inappropriate, or overly complex activities (age-appropriateness is a hard constraint, not a preference).
- Instruct the model to NOT fabricate video links or image references — those are injected by the backend, not generated by the AI.

## Safety / Content Rules (ages 3–9)
- No violent, scary, or inappropriate themes.
- No requests for personal information from learners.
- Physical activities must be described as low-risk / indoor-classroom-safe.
- If the requested `concept` is nonsensical or unsafe, the AI service should still return a best-effort generic, safe lesson plan rather than failing (soft fallback), while logging the anomaly server-side.

## Error Handling & Fallback
- Timeout/provider error → raise a typed `AIGenerationError`, mapped to `502` in the `lessonPlans.ts` route, with a retry-friendly message.
- Malformed JSON from the model → attempt one retry with a stricter "return valid JSON only" system reminder; if it fails again, raise `AIGenerationError`.
- Rate limiting → surface `429` upstream with a "please try again shortly" message; no silent failures.

## Cost/Perf Notes
- Keep prompts concise; avoid sending uploaded image binary to the LLM (image is just embedded in output HTML, not analyzed by AI in MVP).
- Reasonable `max_tokens` cap sized to `num_activities` (roughly 150 tokens/activity + 300 for other sections) to control cost/latency.
